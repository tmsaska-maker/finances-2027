# T007: переддеплойна інвентаризація фінансового шлюзу

## Мета
Після синтетичного Docker E2E (PR #36, CI #43933272347) перевіряємо, чи реально зможемо безпечно замінити **тільки фінансовий** gateway. Відомо: поточний `finances2027/gateway` займає host loopback 8092; live /finance-api/session без cookie повертає 403. Кандидат на GitHub CI проходить full login → session → private GET → logout.

## Нові поля ручного `inspect-edge` (read-only)
- `finance_runtime_gateway_count_class`, `finance_runtime_api_count_class`: `one / none / multiple`, класифікація контейнерів Compose-проєкту `finances2027`.
- `finance_gateway_rollback_class`: `prerequisites_present` лише якщо всі оголошені у Compose-label конфіг-файли існують у `/opt/finances-2027/` і точний образ **запущеного** контейнера є у кеші Docker. Це лише передумови, **НЕ готовий rollback**, **НЕ резервна копія**.
- `finance_gateway_restart_policy_class`: чи контейнер має автоматичне перезавантаження (без виведення назви policy).
- `finance_gateway_api_network_class`: чи `gateway` і `api` у спільній Docker-мережі, чи `api` має мережевий псевдонім `api`. Це вказує, чи `http://api:8091` має шанс працювати. Це НЕ перевіряє реальну TCP-доступність або авторизацію.

Скрипт не друкує ID/образи/точні шляхи/адреси/секрети/змінні оточення, не читає фінансові таблиці та не змінює Docker, Caddy чи Screening40.

## До production-перемикання ще НЕ виконано
1. Зафіксувати точну версію конфігурації старого gateway та збережений image для відкату **на приватному сервері без виведення секретів у CI**; окремо перевірити метод відкату.
2. Визначити чинний і бажаний Compose merge/override. Ніколи не запускати `docker compose down`; не замінювати image/процес старого шлюзу поза воротами релізу.
3. Зберегти loopback host binding порту 8092. Перед перемиканням виконати окреме тестування кандидата без host port collision, без реальних даних та без опублікування private UI.
4. Перевірити приватний HTTPS origin, policy Caddy, сесії й захист від CSRF, перехід на новий код, логування без чутливих даних, можливість відкату, ізоляцію Скринінгу.
5. Лише після review і явної команди здійснювати finance-only деплой.

**Обмеження:** якщо конфіг label відсутній або старий контейнер створений через додаткові Compose-файли, нові поля класифікують його як непідтверджений. Не робити висновок, що образ можна відтворити тільки за `docker image inspect`.
