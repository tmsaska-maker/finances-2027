# Фінанси 2027 — середовища та просування змін

## Потік
1. Нова функція створюється у `feature/...` і проходить PR.
2. Після тестування її включають у `staging`.
3. Workflow `staging.yml` запускає Node tests, TypeScript, PostgreSQL integration tests, config checks, збірку.
4. Лише після всіх зелених перевірок виходить артефакт `finances2027-staging-release` і оновлюється гілка `site-staging`.
5. Після ручної перевірки staging і затвердження — PR `staging → main`; робочий `main → site` залишається окремим.

## Важливо
`site-staging` — це зібрані статичні файли для staging, **не ознака розгортання на Lightsail**.
Окремого HTTPS staging-піддомену поки немає, Caddy не змінювався.
Фінансовий API не доступний з відкритого браузерного staging, доки немає безпечної користувацької автентифікації.
Ніколи не вводити реальні банківські, зарплатні або медичні дані в демонстраційний сайт.

## Перший staging на сервері (після перевірки ресурсів)
Використати окремий каталог `/opt/finances-2027/staging/site`, але **не** `/opt/finances-2027/site`.
Доступ до staging обмежити авторизацією або приватною мережею. Перед відкриттям піддомену перевірити HTTPS, Caddy, права та плани відкату.
Встановлення PostgreSQL/API/backup на сервері — окрема операція після read-only аудитів і резервної копії існуючих сервісів.

## Мінімальні умови прийняття
- green CI (unit + integration + build);
- збереження UX Figma;
- нуль реальних даних у демо;
- тестове створення зобов'язання, часткової оплати, розрахунку боргу;
- перевірені backup, відновлення, auth і журнал аудиту **перед** продукційною роботою.
