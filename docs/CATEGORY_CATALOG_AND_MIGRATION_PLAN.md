# Фінанси 2027 — довідник категорій та інтеграція наявного інтерфейсу
Статус: **проєкт специфікації для погодження**, не SQL-міграція і не дозвіл на використання реальних даних.

## Зафіксоване рішення
- **Один системний довідник** категорій і підкатегорій зі стабільними ID.
- Для кожного фінансового напряму (ambulatory, screening, psychotherapy, personal) — власний **набір дозволених** категорій/підкатегорій через зв'язувальну таблицю. Одна й та сама сутність може бути доступна кільком напрямам, якщо це справді однакова економічна природа.
- Не змінювати наявний UX екрана «Витрати та зобов'язання» при підключенні БД; серверний екран `?financeServer=1` залишається тимчасовою діагностикою й не є дизайном для продукції.
- Зобов'язання можна вводити вручну. Факт грошового руху переважно **імпортується з банківської виписки**. Готівковий або відсутній у виписці факт — ручний виняток з `source_type=manual`, автором, датою та обов'язковою перевіркою дублікатів.
- Запланований/відправлений платіж не погашає зобов'язання; лише підтверджений, пов'язаний із банківською транзакцією, впливає на суму погашення.
- Категорія витрати **не визначає автоматично** її податковий статус, період або проєкт; це незалежні поля.

## Інвентаризація: категорії з таблиць, не нові назви
Наведені нижче назви є **вихідними даними**, а не остаточним канонічним довідником. На цьому етапі НЕ об'єднувати їх автоматично за схожістю.

### Амбулаторія — приклади структур з «Видатки»
| Категорія/рядок | Дочірні рядки |
|---|---|
| Оренда приміщення договір; Оренда приміщення готівка | окремі історичні рядки, питання: це різні підкатегорії чи спосіб оплати? |
| Обладнання | Медичне; Побутове; Рекламне |
| Комунальні платежі | Опалення; Вода; Електрика; ОСББ + Сміття; Інтернет |
| Оплата підрядникам | Лабораторія; ЛКК; УТОГ |
| Розхідні матеріали та послуги | Реактиви; Канцтовари; Розхідні матеріали; Інші послуги; Банк |
| Оплата кредиту | кредитка; Обладнання |
| Реклама | Креативи |
| Зарплата персоналу | медсестра #1/#2, лікар #1/#2/#3, премії, оплата платних прийомів |
| Відпускні | медсестра; лікарі |
| Податки на зарплату | історично: ЄСВ 22%, ЄСВ за ФОП, військовий ФОП — перевірити відповідно до новіших затверджених правил |
| Фінансування інших проектів | Скринінг 40+; Психотерапія — НЕ автоматично операційні видатки |
| Податок з доходу | 5% |

### Скринінг — з «Видатки»
Адміністратор, зарплата; Податки ФОП; Зарплата персоналу (лікарі, медсестра); Лабораторні обстеження (Пакет обов'язковий, Пакет розширений, Пакет «Анемія»); Фінансові (Банк %, Банк еквайринг); Податки на зарплату; Податок з доходу. Перевірити узгодження зі спільними податками ФОП.

### Особисте — з «БЮДЖЕТ», «Видатки_ПЛАН»
Групи `БАЗА`, `СТИЛЬ ЖИТТЯ`, `ПРОЄКТИ / ВЕЛИКІ ПОКУПКИ`, `ФІНАНСОВІ КОНТУРИ — НЕ СПОЖИВАННЯ`.
Приклади: Харчування/Продукти; Житло/Комунальні Тернопіль, Комунальні Київ, Побутові товари; Транспорт/Пальне, Таксі, Поїзд; Зв'язок/Інтернет, Телефон, Підписки; Здоров'я/Ліки, лікарі, психотерапія, спорт; Домашні тварини/Корм, Ветеринарія; Діти/Настя, Стас; Одяг та взуття; Дозвілля та розвиток; Навчання; Подорожі.
Окремий НЕспоживчий контур: погашення тіла кредиту, накопичення, фінансування власних проєктів; не змішувати їх із фактичними витратами на споживання.

### Психотерапія
Окремий проєкт уже затверджено; точна номенклатура категорій НЕ перевірена за профільною таблицею. Не вигадувати і не переносити категорії Амбулаторії автоматично.

## Цільова структура даних (концепт; міграцію не виконувати)
- `categories(id, code, name, parent_id, economic_type, active, sort_order)`; `parent_id` для підкатегорії.
- `project_category_access(project, category_id, enabled)`; лише доступність для вибору, не нова копія категорії.
- `category_aliases(id, project, source_file, source_label, category_id, confidence, reviewed_at)`: контрольоване перенесення старих назв, без втрати історії.
- `transactions`: `source_type` (bank_import/manual), стабільне джерело, унікальність/ідемпотентність, категорія/підкатегорія, tax_status, project, account_id, occurred_on, report_period, reconciliation state; окремо `transfer_group_id` для внутрішніх переміщень.
- `obligations`: план, строк, категорія, очікуваний рахунок; не прирівнювати до транзакції.
- `payments`: алокації підтверджених банківських транзакцій до зобов'язань; не подвоювати їх як нові витрати.
- Версіоновані правила класифікації й журнал аудиту/коригувань.
- Для міграції: спочатку нові таблиці й read-path, потім адаптер API, потім переключення джерела даних **всередині того самого React-екрана**. Заборонити паралельний незалежний localStorage-факт після переключення.

## Важливі затверджені правила з ФІНАНСИ_АРХІТЕКТУРА
- Один ФОП, декілька проєктних P&L, єдиний податковий контур.
- Банківське надходження не дорівнює автоматично оподатковуваному доходу.
- `payment_date` і `tax_period` — різні виміри; суми не дублювати між проєктами.
- ЄСВ ФОП не утримується із зарплати власниці; відображати окремо.
- Внутрішнє фінансування Скринінгу Амбулаторією та повернення/борги — окрема логіка міжпроєктної звірки, не друга копія витрати.

## Відкриті рішення
1. Які історичні «рядки категорій» фактично є контрагентами/способами оплати/співробітниками/типами руху, а не категоріями?
2. Чи допускаємо ручну витрату без банку тільки для готівки/винятків? Рекомендація: так, з позначкою і звіркою.
3. Підтвердити повний профільний довідник Психотерапії.
4. Визначити правила розподілу однієї транзакції між категоріями та проєктами без дублювання.
5. Підтвердити які категорії є управлінськими, які податковими, які — лише фінансовими переміщеннями.

## Критерії готовності перед підключенням UI
- Затверджено зіставлення категорій з джерелами і список доступності за проєктом.
- Імпорт банківських виписок повторним запуском не дублює транзакції.
- Банк/готівка/міжпроєктні перекази не формують подвійного видатку.
- Підтверджений банківський платіж може частково погасити одне чи декілька зобов'язань; черга не погашає.
- Працює звірка та журнал аудиту; збережено існуючий UX.
- Тести відтворюють відомі сценарії з Google-таблиць (з анонімізованими сумами), включно з міжпроєктними боргами й податками.
