# T007: gate для проєктування функціональної репетиції старого шлюзу

## Підстави й підтверджені факти

Оригінальний Docker snapshot pinned at `8bf0f2b0a59909bbff3a667e7c025b192123acdc` має підтверджений SHA256 архіву, статичні метадані запуску, а остання перевірка `inspect-gateway-snapshot` №44141921370 знайшла **додаткові чутливі ENV**, не виявивши додаткових network ENV. Попередні запуски старого образу в контейнері `--network none` і лише з синтетичними ENV завершились `application_exit_1`. Реального секрету в CI немає, і причинний зв'язок між додатковими ENV та виходом 1 **не доведений**.

Новий кандидат gateway та синтетичний `legacy-fixture` не визначають точно поведінку збереженого оригінального образу. Зокрема, 403 від fixture **не є доказом**, що оригінальний gateway мусить відповідати 403.

## Нова перевірка: без запуску та розгортання

`deploy/gateway-functional-rehearsal-gate.py` містить **чисту функцію** `assess(evidence)` з фіксованим словником вхідних ознак. Її тестують на фіктивних комбінаціях у CI; вона не виконує Docker, не читає приватних файлів чи ENV, не встановлює з'єднань і не змінює сервер.

Ключові незакриті докази:
1. **Синтетичний конфігураційний контракт:** встановити, які саме типи налаштувань потрібні старому образу та які синтетичні замінники зберігають потрібний формат без використання справжніх ключів, адрес чи токенів. Не копіювати `running-container.json`, `running-image.json` і приватні значення з Lightsail у GitHub.
2. **Автентичний HTTP-контракт:** визначити критерій безпечного анонімного запиту саме для старого образу, не прирівнюючи його до синтетичного fixture.
3. **Незалежна ізоляція:** будь-яка майбутня репетиція повинна залишатись без доступу до API, DB, Caddy, production мережі, host ports, mounts та секретів; без можливості перезапуску працюючих контейнерів.

За реально наявних T007 доказів рішення — `blocked_missing_synthetic_contract`. Навіть якщо обидва невідомі контракти коли-небудь будуть підтверджені, максимальний результат цього gate — `ready_for_isolated_design`, **а не** `rollback_rehearsal_passed` чи дозвіл `deploy`.

## Чого цей PR навмисно НЕ робить

- Не змінює `manual-finance-deploy.yml`, startup старого образу та правила продакшн-релізу.
- Не запускає жодних операцій на Lightsail.
- Не підбирає значення приватних ENV і не проводить функціональну репетицію автоматично.
- Не стверджує, що причина `application_exit_1` встановлена.

**Після green CI:** наступна робота — розробити безпечний спосіб перевірити формат синтетичних налаштувань, не передаючи навіть назви й значення додаткових приватних ENV у GitHub. Доки це не доведено, повторне запускання старого образу недоцільне; production rollback і release лишаються заблокованими.
