# F02 — окреме розгортання на AWS Lightsail (підготовка, НЕ виконано)

## Важливе
Цей документ **не означає**, що база чи API вже встановлені. Реальні дані ще не вводити.
Наявна система `Скринінг 40+` працює окремо: не змінюємо її Docker Compose,
PostgreSQL, томи, порти, контейнерні мережі або правила Caddy.

## Ізоляція
- Окрема директорія source: `/opt/finances-2027/backend` (гілка `main`), не замінювати існуючу `/opt/finances-2027/site` (гілка `site`).
- Окремий Compose project: `finances2027`, власний том `finances2027_db`, власна мережа.
- PostgreSQL **без відкритого порту** на хості. Finance API лише `127.0.0.1:8091`.
- Ніякого нового маршруту Caddy для API, доки немає користувацької автентифікації/авторизації.
- Секрети тільки в `deploy/.env` на сервері (режим `600`), ніколи у GitHub, ZIP, скриншотах чи публічному HTML.

## Передвстановлювальна перевірка (read-only)
На існуючому Lightsail у SSH, без внесення змін:
```bash
docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
docker compose ls
free -h
df -h /
sudo ss -lntp | grep -E '(:80|:443|:8080|:8091|:5432)' || true
sudo docker volume ls
```
Зібрати лише інформацію про ресурси та назви; **не ділитися секретами**. Додатковий PostgreSQL
потребує запасу RAM/disk; на сервері Скринінгу це потрібно перевірити окремо.
Переконатися, що доступні бекапи працюючої системи Скринінгу, і відновлення протестоване.

## Підготовлений пакет
- `deploy/compose.yaml`: лише два нові finance-сервіси `db` і `api` з власним томом.
- `server/Dockerfile`: контейнер Node.js для приватного API.
- `server/sql/001_initial.sql`: початкова міграція в нову finance-БД.
- `deploy/backup.sh`: `pg_dump` тільки фінансової бази, список відновлення через `pg_restore --list`.
- `deploy/restore-drill.sh`: пробне відновлення фінансового дампа в НОВУ тимчасову
  finance-БД, після перевірки видаляє тільки її.

## План контрольованого першого запуску (НЕ виконувати автоматично)
1. Зробити резервну копію/снапшот Lightsail і перевірити відновлення Скринінгу.
2. Зібрати main репозиторію в `/opt/finances-2027/backend`, не чіпати `site`.
3. Згенерувати випадкові секрети; `deploy/.env` закрити правами `600`.
   Пароль БД повинен бути URL-safe (бо використовується в DATABASE_URL).
4. Запустити **тільки** finance `db`, перевірити healthcheck і споживання пам'яті.
5. Внести `server/sql/001_initial.sql` **лише** в finance-БД.
6. Запустити finance `api` на `127.0.0.1:8091`, виконати закритий локальний smoke test.
7. Провести пробний фінансовий `pg_dump` і відновлення в тимчасову базу.
8. Налаштувати регулярне резервне копіювання, шифрований off-site backup,
   моніторинг диску/помилок і реальний сценарій відкату. Лише після цього — наступний етап.

## Відкат
Зупиняти **лише** finance compose, з директорії `deploy`:
```bash
docker compose --env-file .env -f compose.yaml stop api db
```
**НЕ використовувати** `docker compose down -v`, `docker volume prune`,
`docker system prune`, глобальне видалення контейнерів/томів.
Не зупиняти жоден `screening40-*` контейнер.
Керування даними finance-БД і видалення тому потребують окремого рішення.

## Межі захисту
Поточний API має спільний технічний ключ, але **це не авторизація користувачів**.
Немає журналу аудиту й гарантованих off-site копій. Поки не інтегрувати з публічним
frontend і не вводити справжні банківські, зарплатні чи медичні дані.
